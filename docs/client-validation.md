## 실제 앱에서 확인할 순서

개인 자료가 없는 가상 공고로 진행한다. 이미지에 가상기업·예시 직무·미정 마감과 긴 본문을 넣는다.
실제 회사 공고나 개인정보를 공개 이슈에 첨부하지 않는다.

1. 클라이언트 이름·버전·OS·날짜를 기록하고 JobShot MCP 도구 3개가 보이는지 확인한다.
2. Windows 캡처 CLI를 확인하려면 가상 공고를 캡처하고 명령을 실행한다. 출력된 `image_path`와 실제 `inbox/` 파일을 대조한다.
3. 해당 경로를 `posting_import`에 전달한다. 원본·manifest·분할본을 열어 순서와 경계의 글자가 누락되지 않는지 확인한다.
4. 같은 입력을 다시 보내도 공고 폴더가 늘어나지 않고 `duplicate: true`인지 확인한다.
5. 대화창 붙여넣기 경로는 따로 확인한다. 이미지가 보이는 것과 로컬 첨부 파일 경로를 사용할 수 있는 것은 구분한다.
6. 첨부 경로를 사용할 수 있으면 원본을 이동하지 말고 `inbox/`로 복사한 뒤 입력한다. 경로 접근이 불가능하면 캡처 CLI 또는 파일 저장 대안이 안내되는지 확인한다.
7. 날짜가 미정으로 남고 달력 등록이 발생하지 않는지, 개인 자료 원본이 변하지 않는지 확인한다.

OS 클립보드 검증은 사용자가 캡처를 준비한 상태에서 수행한다. 테스트를 위해 기존 클립보드를 덮어쓰지 않는다.
현재 작업에서는 이 수동 절차를 실행하지 않았으며, 앱 UI 지원 완료로 표시하지 않는다.

```text
날짜 / OS / 클라이언트 버전:
입력 경로: 파일 / Windows 캡처 CLI / 대화창 첨부
도구 발견:
첨부 경로 접근 여부:
원본 보존 / 분할 좌표 / 경계 글자:
재입력 / 미정 날짜 / 일정 미등록:
실패 시 안내:
남은 제한:
```

공개 기록에는 토큰·개인 경로·실제 파일 본문을 넣지 않는다.
