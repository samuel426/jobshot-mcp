# 구조와 데이터 설계

상태: 4단계 Google 선택 전송 첫 구현. `profile_list`, `profile_read`, `posting_import`, `posting_list`, `posting_track`, `dashboard_build`, `posting_get`, `posting_save_analysis`, `application_save`, `calendar_preview`, `calendar_sync`를 제공한다.
AI 판단과 문장 작성은 클라이언트가 수행하고 MCP는 평가 구조·자료 버전·인용·배점을 검증한다. Google 실제 계정 검증은 남아 있다. 사용법은 [시작하기](getting-started.md)를 따른다.

## 역할 분리

- AI 클라이언트: 사용자가 선택한 이미지·개인 자료를 읽고 공고 해석·비교·문장 작성을 수행한다.
- 로컬 MCP: 지정 작업 폴더의 읽기·쓰기, 데이터 검증, 달력 생성과 선택적 Google 연동을 담당한다.
- 저장소: 사람이 열어볼 수 있는 JSON·Markdown·이미지 파일로 시작한다.
- HTML: 등록된 공고만 포함한 생성물이다. 원본 데이터는 JSON이고 HTML을 직접 편집해 상태를 바꾸지 않는다.

별도의 AI API 키나 개발자 중계 서버를 필수로 만들지 않는 방향으로 설계한다.
Node.js 24 + TypeScript, 공식 MCP TypeScript SDK v2.3.1의 stdio 전송을 사용한다.
Zod는 입력 검증, sharp는 이미지 검증·EXIF 방향 적용·분할을 담당한다. 정확한 버전은 package-lock.json으로 고정한다.
공식 MCP 클라이언트와 2025-11-25 JSON-RPC 연결을 테스트한다. npm 공개 배포는 아직 하지 않는다.

## 작업 폴더

```text
개인 자료/                          사용자가 관리하는 원본, AI는 읽기만 함
공고/
  2026-11-01_예시기업_백엔드/
    사진/
      original-001.png             원본
      crop-001.png                 필요할 때만 만드는 파생 이미지
      manifest.json               원본 연결, 해시, 분할 순서와 좌표
    공고정보.json
    분석.md
    지원서류/                      요청 시 생성, 버전별 보존
dashboard/index.html                생성 달력, Git 제외
.jobshot/                           로컬 설정·인덱스·동기화 메타데이터, Git 제외
skills/jobshot-coach/SKILL.md         사용자 지원 절차, 공개 가능
```

폴더가 없는 clone 환경에서는 첫 실행 때 생성한다. 개발용 원본과 개인 자료를 혼합하지 않는다.
현 작업 폴더 이름은 바꾸지 않는다. 다른 사용자가 clone하면 기본 폴더 이름은 `jobshot-mcp`다.

## 공고 계약 초안

| 필드 | 의미 |
| --- | --- |
| schema_version | 형식 버전, 초안은 1 |
| id | 경로 변경에도 유지되는 공고 식별자 |
| company / role | 기업과 직무, 미확인 항목은 명시 |
| source_url | 사용자가 제공하거나 확인한 http(s) 원문 주소, 없으면 null |
| source_images | 원본의 작업 폴더 기준 상대 경로. 분할본 경로·좌표는 사진/manifest.json의 crops에 기록 |
| deadline | 원문, 날짜, 시각, 시간대, 확정 여부 |
| requirements | 필수·우대·전형별 요구사항과 원문 근거 |
| status | imported / analyzed / tracked / submitted / closed / archived |
| profile_sources | 사용한 개인 파일의 상대 경로·해시·확인 시각 |
| evaluation | 평가 기준 버전, 근거, 정보 부족 항목, 점수 |
| calendar | 전송 전 null. Google 전송 시 대상·이벤트 ID·etag·마지막 전송 내용·시각·결과·오류 기록. 로컬 달력 등록으로 변경하지 않음 |
| tracking_previous_status | 로컬 등록 전 imported/analyzed 상태. 해제 시 복원하고 필드 제거 |
| created_at / updated_at | 기록 시각 |

## 경로와 이미지

- 날짜 미확정은 `마감미정_기업_직무`, 상시 채용은 `상시_기업_직무`로 저장한다.
- Windows 금지 문자·예약 이름·끝 공백/마침표를 정규화하고 긴 경로를 제한한다.
- 동일 폴더명은 짧은 공고 ID로 구분한다. 원본 파일 해시로 재입력 중복을 확인한다.
- 날짜 수정 시 이름 변경과 인덱스 갱신은 기존 자료를 덮어쓰지 않도록 처리한다.
- 작업 루트 밖 경로, `..`, 심볼릭 링크/정션을 통한 쓰기 탈출을 차단한다.
- 긴 이미지는 원본을 수정하지 않고 읽기 가능한 분할본을 만든다. 분할 좌표·겹침·순서를 기록한다.
- EXIF 방향을 적용한 표시 높이가 2,000px를 넘으면 전체 폭을 유지한 최대 1,600px 높이 조각을 160px 겹쳐 만든다. 축소하거나 OCR로 문단 경계를 추정하지 않는다.
- 좌표는 `exif_oriented_pixels` 기준이며 원점은 왼쪽 위다. manifest에 표시 크기, 원본 EXIF 방향, 조각별 좌표·순서·겹침·해시·원본 파일 연결과 정책 버전을 기록한다.
- 분할본은 최대 64장, 장당 20 MiB, 합계 100 MiB다. 초과하면 전체 새 공고 저장을 취소하고 입력 원본은 유지한다.
- 파일 쓰기는 임시 파일 후 교체를 사용하고 실패 시 기존 기록을 보존한다. 동시 쓰기 충돌도 처리한다.

첫 구현은 `.jobshot/import.lock` 디렉터리로 저장 작업을 직렬화하고,
원본과 모든 분할본이 완성된 `.pending-*` 폴더를 최종 이름으로 옮긴다. 일시적 이동 오류는 최대 3회 재시도하며 매번 목적지 충돌을 검사한다.
중복은 이미지 해시와 정규화한 입력 메타데이터로 식별한다.
현재 조회/저장 도구는 지정 작업 폴더를 기준으로 경로·정션·파일 크기를 검사한다.
이는 악성 로컬 프로세스의 동시 파일 교체까지 격리하는 OS 샌드박스를 대신하지 않는다.

원본 저장만 끝난 상태를 `analyzed`라고 부르지 않기 위해 `imported`를 추가했다.
`posting_import` 자체는 평가·일정 등록을 수행하지 않는다. 개인 자료 본문 추출은 UTF-8 TXT·MD·JSON부터 지원한다.
재입력 시 원본과 분할본 해시를 확인한다. 이전 버전의 분할 정책 없는 기록은 `legacy_unsplit`로 반환하고 수정하지 않는다.
기존 공고의 분할본 추가·재생성은 후속 작업이다.

Windows 캡처 CLI는 사용자가 실행할 때 STA PowerShell로 현재 클립보드 이미지 한 장을 PNG로 변환해 `inbox/`에 저장한다.
클립보드 내용 변경·텍스트 읽기·상시 감시는 하지 않는다. 이 PNG가 보관할 원본 입력이 되며,
클립보드에 들어오기 전 파일의 인코딩·메타데이터까지 보존한다는 의미는 아니다. MCP 서버는 OS 클립보드에 접근하지 않는다.

## 날짜·달력

현재 시간대는 `Asia/Seoul`로 고정한다. 시간대 설정 기능은 후속 작업이다.
날짜만 알면 시간을 23:59로 만들지 않고 `time: null`과 `시간 미확인`을 표시한다.
연도나 날짜가 불명확하면 자동 일정 등록을 멈추고 해당 항목만 확인한다.
등록을 원한 날짜 미정 공고는 달력 아래 별도 목록에 표시한다.

오늘 표시는 고정 날짜가 아니라 설정 시간대의 현재 날짜를 기준으로 계산한다.
월 이동 중에도 오늘 강조와 오늘 버튼은 유지하되 사용자가 보는 월을 임의로 되돌리지 않는다.
마감 지난 공고를 새 공고처럼 표시하지 않는다. 지난 일정도 기록은 보존한다.

HTML에는 등록된 공고의 최소 정보만 넣고 개인 이력서 본문은 넣지 않는다.
파일을 직접 열 수 있도록 필요한 데이터를 JSON으로 안전하게 내장한다. 외부 스크립트·폰트·네트워크 요청이 없다.
공고 텍스트를 HTML로 실행하지 않도록 escape하고 링크는 http(s)만 허용한다.

`posting_track`은 ID와 등록 여부를 받아 imported/analyzed ↔ tracked 상태만 변경한다. Google 필드·개인 자료·원본 이미지는 수정하지 않는다.
입력·등록·달력 재생성은 같은 `.jobshot/import.lock`을 사용한다. 변경 파일은 같은 디렉터리의 임시 파일을 원자적으로 교체한다.
HTML 출력 경로를 먼저 검사하고 상태를 저장한다. 그 이후 HTML 쓰기만 실패하면 `dashboard_updated:false`와 재생성 안내를 반환한다. 저장된 등록 상태를 성공/실패와 함께 명확히 알린다.
재입력은 tracked 상태도 인식하며 등록을 취소하지 않는다. 손상된 공고·중복 ID·지원하지 않는 날짜/링크는 기존 HTML을 유지하고 오류로 알린다.

## MCP 도구

| 도구 | 역할 | 변경 |
| --- | --- | --- |
| profile_list / profile_read | 선택한 개인 자료 조회 | 원본 변경 없음 |
| posting_import | 원본·분할본 보관과 공고 기록 | 로컬 공고만 생성 |
| posting_get / posting_list | 공고 조회 | 없음 |
| posting_save_analysis | 근거·평가 저장 | 해당 공고 분석 갱신 |
| posting_track | 사용자 요청 공고를 달력 대상으로 지정 | 상태 변경 |
| dashboard_build | 등록 공고의 월간 HTML 생성 | 로컬 생성물 갱신 |
| application_save | 요청한 서류·평가 저장 | 별도 버전 생성 |
| calendar_preview | 선택 공고의 Google 전송 내용·최신 해시 확인 | 네트워크 요청 없음 |
| calendar_sync | 선택한 공고를 Google에 등록·갱신 | 외부 쓰기 |

도구가 자체적으로 합격률을 산출하거나 AI 서비스로 몰래 전송하지 않는다.
전달된 분석은 구조 검증을 거치고 확인되지 않은 항목을 구분한다.

## 직무 분석 저장

세부 계약은 [직무 적합도 저장](job-fit.md)을 따른다. 공고 JSON의 원본 바이트 해시를 동시 변경 감지에 사용하고, 이미지 원본과 선택한 개인 자료의 해시를 확인한다. 기록·이미지·자료가 바뀌면 저장을 거부한다. 자료 인용의 존재를 확인하되 공고 이미지 문구와 해석의 의미·사실성은 클라이언트와 사용자가 확인한다.

공고정보.json을 원자적으로 교체한 뒤 분석.md를 생성한다. Markdown만 실패하면 report_updated:false로 JSON 저장 완료를 알린다. 두 파일은 하나의 트랜잭션이 아니며 강제 종료 시 JSON을 기준으로 복구한다. 재분석은 최신 결과로 교체하며 서류 버전 보존 기능과는 구분한다. tracked 공고의 분석은 상태를 유지하고 tracking_previous_status를 analyzed로 갱신한다. 달력 HTML·Google·개인 원본·공고 사진은 변경하지 않는다.

## 지원서류 버전 저장

지원서류의 상세 계약은 [서류 초안·평가 저장](applications.md)을 따른다. 공고·개인 자료의 최신 해시와 인용을 검사하고 `지원서류/<UUID>/`에 JSON과 Markdown을 함께 게시한다. 기존 버전·공고 상태는 변경하지 않는다. 미완성 `.pending-*` 폴더는 버전이 아니며 강제 종료 시 자동 복구하지 않는다. 모든 문항/항목에 평가를 필수로 포함하고 응답에도 전체 평가를 반환한다. 자소서는 v0.1 배점·점수·감점 수치·이유·본문 근거, 이력서는 숫자 점수를 유보한 강점·부족한 근거·개선안을 기록한다.

## Google 연동 경계

사용자 선택으로 앱이 만든 전용 보조 캘린더만 사용한다. `calendar.app.created` 권한 하나를 요청한다.
별도 Windows CLI가 Desktop OAuth의 PKCE·state·127.0.0.1 임시 포트로 연결한다. 토큰은 작업 폴더 밖 LocalAppData에 Windows DPAPI CurrentUser로 보호한다. MCP 입력으로 인증 정보를 받지 않는다.
공개 앱 검증·테스트 사용자 제한·토큰 만료 등 실제 Google 설정 검증은 남아 있다. [연결·해제·복구 안내](google-calendar.md)를 따른다.

첫 버전은 로컬 → Google 단방향 수동 동기화다. 회사·직무·확인된 마감 날짜·공고 링크와 중복·소유 확인용 식별자만 전송한다. 날짜만 확인된 마감을 하루 종일 일정으로 표시한다.
안정적인 이벤트 ID와 소유 표식으로 재시도·409 충돌 시 기존 이벤트를 확인한다. 외부 etag가 바뀌면 차이와 현재 버전을 반환하고 명시적 덮어쓰기 요청 후에만 If-Match 조건으로 갱신한다. 삭제·참석자·반복 일정은 자동 변경하지 않는다.
공고 해시와 비동기 저장 잠금으로 동시 변경을 검사한다. 실패는 `sync_failed`로 남기며 로컬 공고·등록 상태·HTML·원본은 보존한다. 외부 성공 후 로컬 기록만 실패하면 두 결과를 구분하고 같은 ID로 재시도한다.
전용 캘린더 생성 결과가 불명확하면 다시 만들지 않고 연결 표식을 검사하는 복구 명령을 제공한다. 연결 해제는 토큰 비활성화·권한 철회만 수행하며 기존 이벤트를 삭제하지 않는다.
