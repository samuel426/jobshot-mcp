# 개인 자료 관리

## 원본과 결과물

`개인 자료/`는 사용자가 직접 관리한다. AI는 읽기만 하고 원본 수정·이동·삭제를 수행하지 않는다.
관련 자료를 분석할 때마다 다시 읽어 갱신 내용을 반영한다. 불필요한 식별 정보는 분석 입력에서 제외한다.
생성한 초안·평가는 공고별 폴더에 저장하고 기존 결과가 있으면 버전으로 구분한다.
사용자가 원하는 자료를 넣기 전에는 개인 자료를 다른 폴더에서 자동 수집하지 않는다.

## 전송 범위

사용자는 본인 AI 계정에서 분석할 자료를 선택한다. AI 서비스의 데이터 처리는 해당 서비스 설정에 따른다.
JobShot 개발자가 받는 중앙 업로드, 원격 로그, 분석 원문 수집은 두지 않는다.
Google 캘린더에는 선택한 일정의 회사·직무·날짜·원문 링크만 전송한다.
이력서·자소서·적합도 점수는 일정 설명에 자동으로 넣지 않는다.
동기화에는 공고 기반 이벤트 ID·비공개 공고 ID 표식과 무작위 캘린더 연결 표식을 사용한다. 개인 자료 본문·로컬 경로는 전송하지 않는다.

## Git 및 로컬 보관

`개인 자료/`, `공고/`, `dashboard/`, `.jobshot/`, 인증 파일과 로컬 설정은 Git에서 제외한다.
이 규칙은 백업·암호화·삭제 기능을 대신하지 않는다. 이미 추적된 파일에는 제외 규칙이 소급되지 않는다.
OneDrive 등 동기화 폴더에서 사용하면 사용자 설정에 따라 파일이 동기화될 수 있다.
로컬 실행이라는 이유로 다른 프로그램이나 클라우드 백업까지 차단된다고 설명하지 않는다.

공개 예제는 `examples/`에 직접 만든 가상 자료만 사용한다.
오류 보고에는 토큰, 실제 이름·연락처, 지원서 본문, 캡처를 포함하지 않는다.
Google 인증 정보는 Windows `%LOCALAPPDATA%\JobShot\google-auth\<작업폴더 해시>\connection.bin`에 현재 사용자 DPAPI로 보호한다. 프로젝트·OneDrive 작업 폴더에 토큰을 평문으로 쓰지 않는다. 같은 Windows 사용자로 실행되는 다른 프로그램의 접근까지 차단하지는 않는다.
연결 해제는 로컬 토큰을 비활성화하고 Google 권한 철회를 요청한다. 실패 시 Google 계정 설정에서 수동 철회한다. 기존 캘린더·일정은 보존한다. [연결·해제·복구 절차](google-calendar.md)를 따른다.
