# 가상 자료로 첫 사용 체험

실제 이력서나 Google 계정 없이 설치·입력·달력·평가 흐름을 확인한다. 먼저 [배포 준비 안내](release-readiness.md)에 따라 설치하고 `npm run check:release`를 실행한다.

## 자료와 MCP 연결

명령에 출력된 `tmp/release-smoke-*` 폴더에 다음 자료가 있다.

- `개인 자료/가상경험.md`: 사실을 만들어내지 않는 인용 흐름을 위한 짧은 가상 경험
- `inbox/sample.png`: 실제 채용과 무관한 가상 공고. 마감일 미정, 원문 링크 없음
- `dashboard/index.html`: 가상 공고 1개가 날짜 미정 목록에 표시되는 달력
- `공고/…/지원서류/…/초안.md`: 숫자 점수 없이 강점·부족한 근거·개선안을 포함한 이력서 예시
- `result.json`: 검사 결과와 출력 파일의 상대 경로

앱에서 체험하려면 [연결 안내](getting-started.md)의 `dist/cli.js`는 설치 폴더로, `--workspace`는 출력된 샘플 폴더의 절대 경로로 지정한다. 기존 실사용 연결을 덮어쓰기보다 별도 테스트 서버 이름을 사용하고 체험 후 그 항목만 제거한다. 실제 Google 연결은 하지 않는다.

MCP 연결만으로 호스트별 스킬 설치까지 끝나지는 않는다. 대화에 프로젝트의 AGENTS.md와 `skills/jobshot-coach/SKILL.md`를 읽고 그 사용 흐름을 따르도록 요청한다. 해당 클라이언트에서 파일을 읽을 수 없다면 지원 범위를 먼저 확인한다.

## 대화 예시

1. “가상 자료 목록을 보여줘. 가상경험.md만 읽어줘.” 원문과 가상 예시라는 안내를 확인한다.
2. “sample.png를 가상기업·백엔드 개발 공고로 보관해줘. 마감일과 원문 링크는 미정이야.” 기존 검사에서 이미 저장했으므로 중복을 만들지 않고 기존 공고를 반환해야 한다.
3. “이 가상 공고를 로컬 달력에서 해제했다가 다시 등록해줘.” 날짜 미정 목록의 변화와 재생성 결과를 확인한다. 해제는 공고·원본 삭제가 아니다.
4. “가상경험.md를 근거로 이력서를 작성하고 항목별 강점·부족한 근거·개선안을 알려줘.” 없는 성과를 추가하지 않고 새 버전으로 저장하는지, 숫자 점수를 붙이지 않는지 확인한다.
5. “없는자료.md를 읽어줘.” 누락 파일을 만들거나 성공했다고 응답하지 않고 실제 파일명 확인을 안내해야 한다.

자소서를 체험하려면 질문과 분량 기준을 함께 제공한다. 예: “직무 관련 경험을 500자 이내, 공백 포함으로 작성해줘.” 항목별 점수·근거·감점 이유가 나오는지 확인한다. 가상 자료가 부족해 미확인 사실이나 유보 점수가 생길 수 있다. 실제 지원 플랫폼의 글자 수 대조는 별도다.

## 수동 피드백 기록

참여에 동의한 사람에게만 요청한다. 자동 사용량 수집이나 연락은 하지 않는다. 개인 자료·화면 전체·계정·인증 로그를 제출받지 않고 아래 항목을 익명으로 기록한다.

| 항목 | 기록 |
| --- | --- |
| 환경 | OS, Node 주 버전, AI 클라이언트·버전 |
| 첫 실행 | 안내만으로 설치했는지, 막힌 단계와 개인정보를 뺀 오류 코드 |
| 입력 | 파일 위치와 저장/분석의 차이가 이해됐는지 |
| 달력 | 날짜 미정·오늘·월 이동·원문을 찾기 쉬웠는지 |
| 서류 | 점수 이유 또는 강점·부족 근거가 수정에 도움이 됐는지 |
| 휴대전화 | 기종/브라우저, 터치·가로 이동·링크 결과; 미실행이면 미실행 |
| 다음 개선 | 가장 불편했던 한 가지, 다시 사용할 의향 |

실패한 단계는 [오류와 복구](getting-started.md)를 참고하고 재확인 결과를 남긴다. 예시 실행 성공을 실제 사용자의 독립 설치 완료로 기록하지 않는다.
