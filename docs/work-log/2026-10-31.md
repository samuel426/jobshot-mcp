# 2026-10-31 작업 기록

실제 연결·이벤트 검증과 코드는 10월 31일 작업이며, 중단 후 11월 1일에 제출 작업을 이어서 진행한다.

## 범위

- 오늘 작업 요청에 따라 [이슈 #5](https://github.com/samuel426/jobshot-mcp/issues/5)의 Google 연동 실사용 검증과 인증 만료 개선을 진행했다. 기존 `codex/google-calendar` 브랜치와 [PR #16](https://github.com/samuel426/jobshot-mcp/pull/16)에 이어서 반영한다. 5단계 배포는 시작하지 않았다.
- 사용자 제공 Desktop OAuth 설정으로 실제 Windows 계정 연결·전용 캘린더 생성을 완료했다. 사용자가 별도로 가상 테스트 일정 1개의 생성·수정·삭제를 승인했다.
- 실제 자료·인증 정보·계정 주소·캘린더 ID는 커밋·이슈·PR·테스트 픽스처에 포함하지 않는다. 실행용 가상 공고와 결과는 Git 제외 tmp/에 두었다.

## 변경

- 실제 동의 과정에서 3분이 지나 콜백이 종료되는 문제를 확인했다. 기본 대기를 10분으로 늘리고 CLI 안내와 구현이 같은 상수를 사용하도록 했다.
- 시간 초과는 `GOOGLE_AUTH_TIMEOUT`, 취소·인증 주소 표시 실패는 `GOOGLE_AUTH_CANCELLED`로 구분한다. 시간 초과 시 이전 탭을 닫고 같은 명령의 새 주소로 재시도하도록 안내한다.
- 시간 초과가 기존 연결을 보존하고 콜백·잠금을 해제하며 다음 시도에서 같은 캘린더를 재사용하는지 회귀 검증을 추가했다.
- Google Calendar REST API 준비, 만료 복구, 현재 대화 MCP와 실제 연결 작업 폴더의 차이, 실제 검증 범위를 문서에 반영했다.

## 검증

- 실제 Google API: 가상 일정 생성·재조회, 재전송 시 insert/patch 없음, 같은 이벤트 ID의 날짜 수정, 오래된 로컬 미리보기 거부, 외부 수정 보존·충돌 보고·명시적 해결을 확인했다.
- 승인된 테스트 일정만 소유 표식·최신 etag를 확인해 삭제하고, 삭제 후 자동 재생성이 차단되는지 확인했다. 테스트 일정 정리 완료. 원본 이미지와 로컬 imported 상태 보존을 확인했다.
- 현재 대화 MCP: 도구 11개 노출, `calendar_preview` 성공·날짜 미정 거부, `calendar_sync`의 미연결 오류와 실패 후 공고·원본 해시 보존을 직접 확인했다. 가상 자료용 MCP를 실계정과 연결하지 않았다.
- Windows `npm run check`: 73개 통과, 실패·건너뜀 0. 빌드·문서 링크·Git 제외 검사 통과. 샌드박스의 루프백 EACCES·정션 EPERM을 확인하고 권한이 있는 실행 환경에서 전체 검사를 통과했다.

## 남은 작업

- 실제 지원 공고 전송 전, MCP와 계정 연결 CLI가 같은 작업 폴더를 사용하는 실사용 설정을 확인한다. 현재 대화의 실제 Google 전송 성공으로 기록하지 않는다.
- Google 화면의 일정 표시, 실제 권한 철회·재연결, 공개 배포용 OAuth 검토가 남아 4단계를 전체 완료로 표시하지 않는다. 살아 있는 연결을 검증 목적으로 해제하지 않았다.
- 서류 도구 현재 대화 직접 호출·사용자 작성 흐름, macOS·Claude Code·새 환경 설치·모바일·친구 피드백은 기존 후속 범위다.
