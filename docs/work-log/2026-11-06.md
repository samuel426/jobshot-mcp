## 범위와 구현

- PR #26 병합 커밋 `6e7d023`에서 이슈 #27과 `codex/vercel-prototype` 브랜치를 만들었다. 사용자는 본인 Vercel 계정으로 배포·관리하고 화면은 가상 관리자 모드로 제공하기로 결정했다.
- `web-prototype/public`의 정적 HTML·CSS·JavaScript로 지원 달력, 공고 보관함, 서류 예시, 관리 설정을 구성했다. 월 이동·오늘·목록 전환, 공고 검색·빈 결과, 상세 대화상자와 예시 서류 전환이 동작한다.
- 모든 공고·자료는 가상이며 저장·업로드·실제 AI 평가·Google 연결·로그인은 구현하지 않는다. 자소서는 예시 점수와 이유, 이력서는 정성 평가를 표시한다. 비밀번호·인증 정보·개인 자료는 소스와 배포에 포함하지 않았다.
- 기존 MCP 코드와 개인 작업 폴더는 변경하지 않았다. 별도 루프백 미리보기 서버와 Vercel 정적 배포 설정·제외 규칙을 추가했다.

## Vercel 설정과 배포

- 사용자 요청의 [공식 시작 안내](https://vercel.com/get-started.md)를 따라 CLI 65.11.0, 공식 Vercel Codex 플러그인 0.21.3, 전역 MCP 서버를 설정했다. 사용자가 CLI 로그인을 마쳤으며 MCP OAuth도 완료됐다.
- 별도 App Server 임시 세션에서 MCP 도구 발견·문서 검색·인증된 팀 목록 읽기 호출 성공을 확인했다. MCP 팀 목록 결과는 비어 있었으며 프로젝트 접근 확인과 배포에는 계정·팀을 확인한 CLI를 사용했다. MCP 쓰기 승인을 유지했다.
- 사용자 소유 프로젝트 `samuel426s-projects/jobshot-web-prototype`를 생성·연결했다. 연결 시 자동 생성된 환경 파일은 내용 출력 없이 제거했다. 이 정적 화면에는 환경 변수가 필요 없다.
- dry run에서 HTML·CSS·JavaScript·vercel.json·제외 규칙의 5개 파일만 업로드됨을 확인했다. 실제 배포는 READY 상태이며 [공개 주소](https://jobshot-web-prototype.vercel.app)의 익명 HTTP 200과 noindex·nosniff 헤더를 확인했다.
- 현재는 CLI 수동 배포다. Git 자동 배포 연결은 설정하지 않았다. 앱의 관리자 표시는 접근 제어나 인증 기능이 아니다.
