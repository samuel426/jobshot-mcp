# 2026-11-01 작업 기록

## 범위와 결정

- 사용자가 PR #16 병합을 알린 뒤 남은 작업과 Google 실패 시 로컬 웹 대체 동작을 요청했다. merge commit `4c37533233c24ea124ff69bc8cc47a6be582ff53`을 확인하고 최신 main에서 `codex/calendar-local-fallback` 브랜치를 만들었다.
- [이슈 #17](https://github.com/samuel426/jobshot-mcp/issues/17)에 범위와 완료 조건을 기록했다. 사용자는 실패 시 로컬 달력 자동 등록과 결과 안내를 선택했다. R06/R13 및 AI 지침을 변경해 기존 별도 선택 원칙에 이 예외를 명시했다.

## 구현

- calendar_sync의 Google 결과를 유지하면서 연결·전송 실패 또는 충돌 시 같은 공고를 로컬 tracked 상태로 등록하고 HTML을 생성한다. Google 성공은 기존 로컬 등록 상태를 유지한다.
- local_calendar에서 등록 성공·HTML 갱신 성공·부분 실패·미시도를 구분한다. Google 응답 유실과 충돌 정보를 숨기지 않으며 Google 성공으로 오인시키지 않는다.
- 대체 등록 직전에 최신 공고 해시를 잠금 안에서 확인한다. 오래된 미리보기·동시 변경·로컬 저장 불명확 상태에서는 추가 등록을 중단한다. 등록 후 반환 해시는 새 로컬 상태를 반영한다.
- 로컬 웹에 Google 없이 사용 가능하다는 안내를 추가했다. 등록은 AI 도구로 수행하고 HTML은 조회용으로 제공한다. 서버나 외부 라이브러리 요청은 추가하지 않았다.

## 실사용 연결

- 프로젝트 MCP의 이름을 jobshot으로, 작업 폴더를 실제 Google 계정이 연결된 폴더로 전환했다. 기존 설정은 Git 제외 .codex/에 백업했다. 전역 설정·신뢰·승인 정책·인증 파일은 변경하지 않았다.
- 앱에 포함된 Codex CLI에서 enabled:true 및 제외 사유 없음을 확인했다. 새 stdio 서버의 11개 도구·대체 등록 계약과 기존 Google 전용 캘린더 GET 접근을 확인했다. 개인 자료 본문이나 실제 공고는 읽지 않았고 이벤트 쓰기도 없었다.
- 현재 대화의 기존 MCP 프로세스는 재연결 후 확인해야 한다. 새로운 서버를 직접 띄운 검증을 현재 대화 도구 호출 성공으로 기록하지 않는다.

## 검증과 남은 작업

- Windows npm run check: 80개 통과, 실패·건너뜀 0. 미연결·권한·네트워크·충돌·중복·원본 보존·동시 변경·로컬 출력 실패, stdio와 DOM 확인을 포함한다.
- 가상 공고의 로컬 웹 대체 등록 예시를 Git 제외 tmp/에 생성했다. 실제 자료나 인증 정보는 공개 파일에 포함하지 않았다.
- 현재 대화 MCP 재연결 후 실사용 직접 호출, Google 실제 권한 철회·재연결과 화면 확인, 새 환경 설치·사용자 피드백·다른 OS/클라이언트 검증은 남아 있다.
- 로컬 웹 실제 브라우저·모바일·CSP 검증은 미실행이며 DOM 검증과 구분한다.
