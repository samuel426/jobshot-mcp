# 2026-10-16 — 긴 이미지 분할과 Windows 캡처 입력

## 범위와 협업

[이슈 #2](https://github.com/samuel426/jobshot-mcp/issues/2)의 이미지 입력 경로를 이어 구현했다.
PR #8은 이미 merge commit으로 병합됐고 두 개의 개별 커밋이 main에 보존된 것을 확인했다.
최신 main에서 `codex/image-splitting` 브랜치를 만들었다.
사용자 요청에 따라 앞으로의 기본 병합 방식도 merge commit으로 문서화했다.
오늘 변경은 기능별 커밋으로 나눠 PR 검증 후 병합한다. Squash·rebase로 기존 커밋을 합치지 않는다.

## 구현 결과

- 신규 공고의 표시 높이 2,000px 초과 시 1,600px 높이·160px 겹침의 PNG 분할본 생성.
- EXIF 8가지 방향·반전을 반영한 좌표, 순서, 원본 연결, 해시, 정책 버전 기록. 원본 바이트는 보존.
- 분할 장수·파일 크기 제한, 중간 실패 정리, 재입력 시 원본/분할본 변경·누락 검사.
- Windows 폴더 이동의 일시적 EPERM/EACCES/EBUSY 오류에 최대 3회 재시도. 목적지 충돌은 매번 확인.
- 사용자가 명령을 실행할 때만 현재 Windows 클립보드 이미지를 PNG로 inbox에 저장하는 별도 CLI.
- 같은 PNG의 중복 저장 방지, 빈 클립보드·미지원 OS·접근 실패 안내. 전역 MCP 설정 변경 없음.
- 시작 안내, 구조 문서, 로드맵, 실제 클라이언트 검증 절차 갱신.

## 검증

- 로컬 Windows / Node.js 24.15.0: 27개 테스트 통과, 문서 링크·배점·개인 파일 Git 제외 검사 통과.
- 가상 PNG·JPEG·WebP를 사용해 각 분할본 전체 픽셀과 방향 적용 원본의 해당 영역을 비교.
- EXIF 방향 1~8, 분할 경계·겹침·마지막 행·최대 장수, 중복 입력과 손상/누락 분할본 확인.
- 실제 MCP stdio 클라이언트로 긴 이미지 입력과 반환 좌표 확인.
- Windows STA PowerShell의 PNG 변환을 가상 Bitmap 제공자로 검증. 실제 사용자 클립보드는 읽거나 변경하지 않음.
- Linux CI에서는 Windows PowerShell 전용 테스트 1개를 건너뛰도록 명시. 나머지 공통 동작을 검사한다.
- 전체 검사 도중 폴더 rename에서 EPERM이 한 번 발생했다. 제한된 재시도와 충돌·지속 오류 테스트를 추가한 뒤 통과했다.
- 원격 Windows/Linux CI 결과와 병합 결과는 해당 PR에서 확인한다.

## 남은 범위

실제 OS 클립보드 캡처와 Codex/Claude 대화창 첨부 전달, macOS 실기기는 미검증이다.
[실사용 체크](../client-validation.md)에 따라 가상 공고로 확인해야 한다. 1단계 이슈는 아직 닫지 않는다.
이전 원본 전용 기록은 `legacy_unsplit`로 반환하고 수정하지 않는다. 분할본 추가·재생성은 후속 작업이다.
문단 의미를 이해하는 분할·여러 이미지 병합·PDF/DOCX 추출·AI 분석 자동화·달력·Google 연동은 이번 범위에 포함하지 않았다.
