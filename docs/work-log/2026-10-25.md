# 2026-10-25 — 지원서류 버전 저장과 문항별 평가

## 작업 범위

- 사용자가 오늘 작업 시작을 요청해 이슈 #4의 다음 범위인 자소서·이력서 초안 저장과 자소서 문항별 평가를 진행했다.
- 최신 main에서 `codex/application-drafts` 브랜치를 만들었다. Google 연동과 배포 단계는 진행하지 않았다.
- 사용자 기획 결정: 서류에는 항상 평가와 그 이유를 포함한다. 자소서는 항목별 점수와 어떤 부분에서 점수를 받거나 감점됐는지 보여준다. 이력서는 항목별 강점·부족한 근거·개선안을 제공하고 숫자 점수는 유보한다. 제품 요구사항과 저장 계약에 반영했으며 개인 설정 변경은 아니다.

## 구현

- `application_save`: 공고와 선택 자료의 최신 해시·인용을 검사하고 `지원서류/<UUID>/서류.json`과 `초안.md`를 새 버전으로 보존한다.
- 모든 문항/항목의 evaluation을 필수로 받는다. 자소서는 v0.1 배점·점수·감점 수치·점수 근거·감점/유보 이유·본문 근거, 이력서는 본문 인용에 연결된 강점·부족한 근거·개선안을 기록한다. 이력서의 숫자 점수는 유보한다.
- 전체 평가를 도구 응답에도 반환해 사용자에게 이유를 보여준다. 인사담당자/실무자 관점, 자료·문항·본문 버전과 시각을 함께 기록한다.
- 미확인 사실·충돌·자료 부족·미평가 항목은 총점을 유보한다. 경험 주장을 본문과 원문 인용에 연결하지만 누락된 주장·의미·경력 사실을 서버가 자동 검증한다고 주장하지 않는다.
- 본문을 그대로 보존하고 공백 포함/제외 글자 수를 따로 계산한다. CRLF를 LF로 계산한 Unicode 코드 포인트 기준이며 실제 지원 플랫폼과 다를 수 있다. 모르는 기준은 unknown/null로 남긴다.
- JSON과 Markdown을 임시 폴더에 모두 쓴 뒤 공개한다. 일반 쓰기 실패는 이번 임시 파일만 정리하고 기존 버전을 보존한다. 강제 종료 시 남은 `.pending-*`는 완성 버전으로 취급하지 않는다.
- 공고 상태·직무 분석·원본·달력은 변경하지 않는다. 버전은 `0.3.0-dev.3`다. 이전 버전의 evaluation:null 기록은 보존하지만 새 저장은 평가가 필수다.

## 검증

- Windows `npm run check`: 54개 통과, 실패·skip 없음. 정션 생성 검사는 샌드박스에서 EPERM이 발생해 일반 실행 권한으로 전체 검증했다.
- 새 기능: 자소서/이력서 버전 보존, 원본·공고·달력 불변, 문항별 배점, 점수 유보, Unicode·공백·줄바꿈·분량 경계, 잘못된 근거·키·배점·자료 경로, 최신성·상태·잠금·정션, 두 번째 파일 쓰기 실패·재시도, Markdown 이스케이프, 크기 제한·원본 변경 거부를 검증했다.
- 공식 stdio·2025 MCP 프로토콜에서 9개 도구 발견과 서류 저장·새 버전·오류 응답을 확인했다.
- 평가 누락/null·감점 이유 누락·이력서 숫자 점수·다른 본문 인용·서류 종류와 평가 불일치를 거부하고 기존 버전을 보존하는지 확인했다. 응답과 Markdown에 자소서 점수 내역·이유, 이력서 강점·부족한 근거·개선안이 표시되는지 확인했다.
- Codex 격리 App Server에서 9개 도구 발견, 가상 자료 분석·자소서 평가 내역·이력서 정성 평가 저장과 원본 보존을 확인했다. 모델 턴·영구 대화·사용자 설정 변경은 실행하지 않았다. 상세 가상 검증 결과는 Git 제외 tmp에만 남겼다.
- 문서 링크·평가 배점·개인 자료 Git 제외 규칙 검사를 통과했다. 실제 개인 자료·공고·인증 정보는 사용하지 않았다.

## 남은 확인

현재 대화에는 기존 8개 도구가 노출돼 있고 새 `application_save` 직접 호출은 연결 갱신 후 확인해야 한다.
실제 서류 작성 품질과 사용자 지원 플랫폼 글자 수, 모바일·브라우저 CSP, Claude Code·macOS 실사용, 친구 피드백은 미검증이다.
3단계 전체 완료나 정식 배포 완료로 표시하지 않는다. PR 병합은 별도 사용자 요청 후 진행한다.
