# 2026-10-17 — 실제 캡처 입력과 프로젝트 연결 준비

## 범위

[이슈 #2](https://github.com/samuel426/jobshot-mcp/issues/2)의 실제 입력 검증을 진행했다.
사용자가 가상 공고 이미지를 대화에 첨부했고, 연결 방식은 적절히 판단해 적용하도록 승인했다.
`codex/client-input-validation` 브랜치에서 검증 결과와 지원 범위 문서를 갱신한다.
제품 기능·중복 판정 정책·개인 자료는 변경하지 않았다.

## 연결 설정

- `.codex/config.toml`에 프로젝트 전용 `jobshot_test` 설정을 추가했다. 기존 설정 파일이 있으면 덮어쓰지 않는 방식으로 생성했다.
- `tmp/` 아래 가상 자료 전용 작업 폴더를 지정했다. 전역 설정은 변경하지 않았다.
- 설정 파일은 Git 제외 대상이며 개인 절대 경로를 공개 문서나 PR에 넣지 않는다.
- 공식 MCP SDK 클라이언트에서 도구 3개 발견·호출을 확인했다. 현재 대화의 도구 목록에는 아직 반영되지 않아 앱 재연결 후 직접 호출 확인이 필요하다.

## 확인한 결과

- 첨부 2장(800×620, 622×480)의 실제 경로 접근, inbox 복사 및 첨부 원본 해시·수정 시각 보존.
- 실제 Windows 클립보드 PNG 저장 성공. 두 번째 첨부와 디코딩한 RGBA 픽셀 해시 일치.
- 샌드박스에서는 `CLIPBOARD_UNAVAILABLE`이 발생했다. 허용된 일반 Windows 실행 환경에서 재실행해 성공했다.
- 첨부 2장·클립보드 PNG·별도 가상 긴 공고를 공식 SDK stdio 경로로 저장하고 재입력했다.
- 입력별 원본 바이트 보존, 재입력 중복 반환, 기존 공고 기록·수정 시각 불변 확인.
- 날짜는 unknown, 시각·평가·달력은 null 유지. 개인 자료 없는 테스트 작업 폴더만 사용했다.
- 긴 가상 공고는 3개 분할본 생성 후 각 픽셀과 좌표 비교 통과. 실제 사용자 캡처는 짧으므로 분할되지 않았다.
- 화면 픽셀이 같은 PNG도 인코딩이 다르면 파일 해시가 달라 별도 공고로 저장되는 현재 동작을 확인했다. 의미 기반 중복 병합으로 임의 변경하지 않았다.
- 이미지·상세 검증 JSON은 Git 제외 로컬 폴더에만 보관했다. 공개 문서에는 결과 요약만 기록한다.

## 남은 확인

Codex 앱의 MCP 재연결 후 도구 노출·직접 호출, Claude Code, macOS는 미검증이다.
앱 버전은 수집하지 않았다. PATH에 있는 Codex CLI 0.47.0을 앱 버전으로 간주하지 않는다.
1단계 전체 완료나 달력 단계 착수로 기록하지 않는다.
확인 절차와 범위는 [클라이언트 실사용 체크](../client-validation.md)를 따른다.
