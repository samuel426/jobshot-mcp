# 2026-11-03 작업 기록

## 재시작 후 확인

- PR #18의 merge commit `bca7f10`을 확인했다. 현재 대화에 실사용 `jobshot` 도구 11개와 로컬 대체 등록 계약이 반영됐다.
- 가상 공고로 현재 대화의 import → preview → sync를 호출했다. Google 미연결 시 원격 요청 없이 로컬 등록·HTML 생성에 성공했고 반복 호출은 변경 없이 종료됐다. 원본 이미지 해시도 유지됐다. 이 확인은 실제 Google 전송 성공이 아니다.
- 기존 정상 사용자 저장소에서 이 프로젝트의 인증 파일을 찾지 못했다. 사용자는 재시작만 했다고 확인했다. 명시적으로 승인한 이전 샌드박스의 해당 프로젝트 파일만 검색했으나 찾지 못했다. 다른 인증 자료는 검색하지 않았다.
- 제한된 실행 환경과 일반 실행 환경의 LOCALAPPDATA가 다름을 확인했다. 파일이 없어진 원인은 확정하지 않았다.

## 연결 복구 개선

- [이슈 #19](https://github.com/samuel426/jobshot-mcp/issues/19)에 범위를 기록하고 최신 main에서 별도 브랜치를 만들었다.
- JOBSHOT_AUTH_HOME으로 CLI와 MCP가 같은 영구 저장소를 명시할 수 있다. 작업 폴더 해시 분리와 DPAPI, 링크·정션 차단은 유지했다. 기존 파일 자동 검색·이동은 하지 않는다.
- 인증 파일이 없는 경우 --connect-existing으로 새 동의를 받고 지정된 기존 전용 캘린더의 ID·JobShot 표식을 조회한 뒤 저장한다. 캘린더/이벤트 쓰기는 없으며 기존 파일이 있으면 덮어쓰지 않는다. 파일 없는 복구에서 원래 작업 폴더의 표식을 대조할 수 없다는 한계를 안내했다.
- 로컬 프로젝트 MCP 설정은 백업 후 일반 사용자 저장소의 절대 경로를 지정했다. 인증·개인 경로는 Git 제외 상태로 유지했다.

## 검증

- Windows 전체 검사: 83개 통과, 실패·건너뜀 0. 가상 응답으로 접근 거부·없는 대상·표식 불일치·네트워크 오류·기존 연결 보존과 원격 생성 없음, 저장 경로 고정을 확인했다.
- 최초 전체 검사에서 기존 인증 시간 초과 테스트에 Windows EFAULT가 발생했다. 인증 테스트 단독 12개와 전체 83개 재실행이 모두 통과했다. 재현되지 않은 오류를 코드 수정으로 해결했다고 기록하지 않는다.
- 문서·Git 제외 규칙 검사 통과.
- 사용자가 새 Google 동의를 완료한 뒤 CLI의 connected:true, created:false를 확인했다. 원래 전용 캘린더 ID를 재사용했고 일반 Windows 사용자 저장소에 DPAPI로 저장했다. 새 프로세스에서 기존 캘린더 GET 접근과 stdio 도구 11개·대체 등록 계약을 확인했다. 이벤트 쓰기는 0건이다.
- 현재 대화의 MCP 프로세스에는 고정 경로 설정을 적용하기 위한 서버 재시작이 남아 있다. 앱 전체 재시작 후 유지 여부와 실제 권한 철회는 미검증이다.
