## 새 복제본 설치 검증

- 기존 개발 PC에서 공개 저장소를 별도 빈 폴더에 다시 clone하고 별도 빈 npm 캐시로 npm ci를 실행했다. 기존 node_modules·빌드 결과·프로젝트 설정·개인 자료·인증 파일을 복사하지 않았다.
- 기준 소스는 `5410e7a`, Windows x64, Node 24.15.0, npm 11.12.1이다. 한글·공백이 있는 경로에서 설치·빌드·npm run check 83개가 통과했다. 실패·건너뜀은 0이다.
- 새 복제본의 기존 check-codex-connection 스크립트와 설치된 Codex CLI 0.166.0-alpha.6을 사용해 격리 CODEX_HOME의 App Server 검사에 통과했다. 도구 11개, 가상 자료 조회·공고 분할·중복·원본 보존·등록/해제·분석·자소서/이력서·로컬 Google 미리보기를 확인했다. 모델 턴과 실제 Google API 호출은 없다.
- 이는 같은 PC의 새 복제본·빈 캐시와 격리 설정 검사다. 새 Windows 설치·다른 사용자 PC·안내만 본 사람의 실제 앱 대화 연결 검증으로 표현하지 않는다. 그 항목은 계속 남긴다.

## 첫 사용 샘플과 라이선스 조사

- check:release를 추가했다. 매번 별도 가상 작업 폴더에 경험 자료·공고 PNG를 생성하고 공식 SDK stdio로 첫 공고·중복·선택 등록·달력·이력서 정성 평가·버전 보존·없는 자료 오류·원본 보존을 확인한다. 저장된 HTML·초안과 result.json을 남겨 수동 체험에도 사용한다.
- 새 스크립트를 새 복제본에도 복사해 같은 설치 의존성으로 실행했고 통과했다. 가상 초안은 사전 작성된 검사 입력이며 AI 생성 품질 검증이 아니다. 실제 사용자 폴더와 Google 연결은 건드리지 않았다.
- 잠금 파일의 직접·전이·개발·선택 의존성 108개를 목록화했다. 선언 누락은 0개다. Windows sharp 패키지의 실제 README·LICENSE를 읽고 네이티브 libvips 등 LGPL 구성요소와 추가 라이선스가 있음을 기록했다. 바이너리 묶음의 재배포 의무 검토까지 완료했다고 표시하지 않는다.
- 새 복제본에서 npm audit --omit=dev가 알려진 런타임 취약점 0개를 보고했다. 해당 시점의 레지스트리 결과이며 개발 의존성·보안 전체 감사와 구분한다.
- Google 공식 문서의 Testing 사용자 제한·7일 refresh token 만료, Desktop OAuth와 운영 프로젝트 준비 요건을 확인하고 안내에 출처를 기록했다. 실제 Cloud 프로젝트·동의 상태를 변경하거나 공개 승인을 받지는 않았다.
