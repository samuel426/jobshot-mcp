# 2026-11-04 작업 기록

## 범위

- 사용자가 이슈 정리 후 다음 작업 시작을 요청해 #4의 현재 대화 서류 작성 흐름을 검증했다. 기존 main의 PR #20 병합 이후 별도 브랜치에서 진행했다.
- 실제 개인 자료가 없는 목록을 확인하고 새 가상 경험 자료와 가상 공고를 준비했다. 실제 경력·공고·인증 정보는 사용하지 않았다. 가상 자료와 결과도 로컬 Git 제외 영역에 보관했다.
- 공고 이미지를 직접 확인하고 현재 대화의 profile_list → profile_read → posting_import → posting_get → posting_save_analysis → application_save를 호출했다. 별도 SDK 세션 결과로 대체하지 않았다.

## 성공 흐름

- 직무 분석 89점과 필수 요건 충족, 참고 평가 안내 및 분석 Markdown 저장을 확인했다.
- 자소서 초안은 126자·85점이며 항목별 배점·점수 근거·감점 이유·본문 인용이 응답과 Markdown에 포함됐다.
- 이력서는 강점·부족한 근거·개선안과 두 관점을 반환하고 score:null 및 qualitative 모드를 유지했다.
- 같은 자료를 다시 읽고 표현을 수정한 자소서를 새 버전으로 저장했다. 수정본은 140자·86점으로, 문장 연결에 따른 가독성 1점 차이다. 점수 상승을 품질 보장이나 합격 확률로 표현하지 않는다.
- 분량·공백 기준 누락을 가정한 별도 버전은 형식 항목 unknown/null, 총점 null, needs_confirmation 및 기준 확인 안내를 반환했다.

## 실패와 보존 확인

- 없는 자료는 FILE_NOT_FOUND와 상대 경로 확인 안내를 반환했다. 자료에 없는 인용은 INVALID_EVIDENCE로 거부됐다.
- 평가 null과 빈 answer_quotes는 MCP 입력 검증에서 저장 전에 거부됐다. 처음 유보 항목의 인용을 빈 배열로 보냈을 때 이 검증에 걸렸고 저장 버전이 늘지 않았음을 확인한 후 본문 인용을 추가해 저장했다.
- unknown 항목도 answer_quotes 최소 1개가 필요하다는 기존 조건을 사용 문서에 명시했다. 제품 코드나 평가 배점은 변경하지 않았다.
- 완성 버전은 초안·이력서·수정본·유보 예시의 4개다. 실패 요청으로 추가 버전이나 임시 버전은 생기지 않았다.
- 첫 자소서 저장 직후의 기존 파일 6개와 최종 파일의 해시를 비교해 공고 기록·분석·원본 이미지·초안 버전이 그대로임을 확인했다. 가상 자료·입력 이미지·기존 달력의 해시와 수정 시각도 유지됐다.
- 공고는 analyzed, calendar:null이며 로컬 달력 등록과 Google 호출은 수행하지 않았다.
- 제출 전 Windows npm run check의 83개 테스트가 모두 통과했다(실패·건너뜀 0). 문서 32개·로컬 링크 67개·Git 제외 규칙과 diff 공백 검사도 통과했다.

## 사용자 피드백과 남은 확인

- 사용자에게 가상 자소서·이력서와 평가를 보여주고 점수 이유·개선안의 이해 여부를 물었다. 사용자는 “이해돼요 — 이 방식 유지”라고 답했다. 가상 예시의 평가 설명 이해도 확인을 완료하고 기존 평가 방식·배점은 유지한다. 실제 지원서 작성 전체의 사용성 검증으로 확대 해석하지 않는다.
- 실제 지원 플랫폼이 정해지지 않아 플랫폼별 글자 수 대조는 수행하지 않았다. 이번 500자 기준은 가상 공고에 명시한 검증 조건이다.
- 이슈 #4에는 직접 호출·수정본·누락 안내와 가상 예시의 사용자 평가 이해도를 완료로 반영한다. 대상 플랫폼 글자 수 대조는 미완료로 남긴다.

## Google 실제 MCP 전송·화면 검증

- PR #21 병합 후 최신 main에서 #5 검증 브랜치를 만들었다. 기존 인증으로 전용 캘린더 읽기에 성공한 뒤 가상 공고 1개를 현재 대화의 posting_import → calendar_preview → calendar_sync로 전송했다.
- 첫 전송은 synced:true, remote_changed:true, local_record_updated:true였다. 다시 미리보고 재전송하면 같은 이벤트 ID로 remote_changed:false를 반환했다.
- Chrome의 Google 캘린더에서 11월 5일 종일 영역의 가상 제목, 상세 팝업의 날짜·마감 시각 미확인 안내·원문 링크·JobShot 전용 캘린더를 직접 확인했다. 실제 계정 화면과 식별자는 공개 기록에 첨부하지 않는다.
- 가상 공고 기록의 날짜를 11월 6일로 변경한 뒤 현재 대화에서 다시 미리보기·전송했다. 같은 이벤트 ID, 새 etag와 날짜 변경을 API 재조회로 확인했다. 날짜 편집 MCP 도구를 새로 구현한 것은 아니다. 입력 이미지와 보관 원본의 해시는 그대로였다.
- 사용자가 이번 권한 철회·재연결 검증을 명시적으로 허용했다. 제품의 disconnectGoogle 경로는 disconnected:true, revoked:true를 반환했다. 이후 현재 대화 calendar_sync는 GOOGLE_NOT_CONNECTED, remote_result:not_attempted와 로컬 tracked:true·dashboard_updated:true를 반환했다.
- 실패 재시도는 로컬 changed:false였고 HTML 데이터의 가상 항목은 1개였다. 수정 날짜·원문 링크도 일치했다. 이 결과는 제품 해제 후 미연결 경로이며, Google 설정에서 외부 철회한 토큰의 401/갱신 실패 실험과 구분한다.
- 사용자 재동의 후 프로그램에서 connected:true, created:false와 이전 캘린더 ID 일치를 확인했다. 현재 대화의 재전송도 synced:true, remote_changed:false여서 기존 캘린더·이벤트를 재사용했다. 로컬 대체 등록은 유지됐다.
- 이번 가상 일정의 소유 표식·제목·반복/참석자 없음·etag를 확인한 뒤 해당 이벤트만 삭제하고 API 조회로 삭제 상태를 확인했다. 삭제 후 calendar_sync 재요청은 자동 승인 검토가 재생성 가능성을 이유로 거부했다. 따라서 이번 직접 호출의 삭제 후 재생성 방지 검증은 완료로 기록하지 않는다. 기존 자동 테스트와 2026-10-31 API 검증 결과는 구분해 유지한다.
- Google 테스트 일정은 정리했고 연결은 정상이다. 로컬 대체 등록의 가상 공고 1개와 원본은 검증 기록으로 남겼으며 실제 공고·개인 자료는 변경하지 않았다. 재동의 주소·인증 정보·실계정 식별자·화면 캡처는 공개 커밋에 포함하지 않는다.
- Windows npm run check 83개 통과, 실패·건너뜀 0. 제품 코드·권한 범위는 변경하지 않았다.

## 로컬 달력 실제 브라우저 검증

- PR #22 병합 후 최신 main에서 #3 후속 브랜치를 만들었다. 가상 공고 6개만 생성하는 수동 검증 스크립트를 추가했다. 개인 자료·실제 공고·인증 파일은 읽지 않으며 기존 달력과 원본도 수정하지 않았다.
- Windows Chrome에서 월 이동·연도 경계·오늘 복귀·가상 원문 새 탭 이동을 직접 확인했다. 자동 DOM 검사와 구분한다.
- 320픽셀 화면에서 오늘 버튼이 두 줄로 쪼개지는 문제를 확인해 toolbar가 필요한 경우 줄을 나누고 버튼/월 제목은 유지하도록 수정했다. 가로 스크롤 안내와 이름 있는 키보드 접근 영역·초점 표시를 추가했다.
- 320·390·768·1440픽셀 화면을 확인했다. 320픽셀에서 월 이동·오늘 복귀, 390픽셀에서 방향키로 오른쪽 날짜 접근, 320/390픽셀에서 날짜 미정·상시 카드 가독성을 확인했다. 실제 휴대전화·터치 검증은 아니다.
- 별도 CSP 검사 페이지에서 제품 정책을 유지하고 nonce 없는 script/onclick, 외부 script·이미지·fetch, eval의 6개 차단을 확인했다. 정상 달력은 실행됐고 검사 대상 루프백 서버 요청은 0건이었다. 검사 코드는 실제 제품 HTML에 포함하지 않는다.
- 검증은 루프백 HTTP로 수행했으며 file:// 접근 제한을 우회하지 않았다. 브라우저 크기를 복원하고 검증 탭·서버를 종료했다. 화면 캡처와 생성물은 Git 제외 tmp에만 저장했다.
- 변경 후 Windows npm run check 83개 통과, 실패·건너뜀 0. 수동 검증 스크립트의 구문 검사도 통과했다. [브라우저 재현 절차](../dashboard-browser-check.md)에 결과와 한계를 남겼다.
