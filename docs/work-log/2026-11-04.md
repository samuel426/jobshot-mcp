# 2026-11-04 작업 기록

## 범위

- 사용자가 이슈 정리 후 다음 작업 시작을 요청해 #4의 현재 대화 서류 작성 흐름을 검증했다. 기존 main의 PR #20 병합 이후 별도 브랜치에서 진행했다.
- 실제 개인 자료가 없는 목록을 확인하고 새 가상 경험 자료와 가상 공고를 준비했다. 실제 경력·공고·인증 정보는 사용하지 않았다. 가상 자료와 결과도 로컬 Git 제외 영역에 보관했다.
- 공고 이미지를 직접 확인하고 현재 대화의 profile_list → profile_read → posting_import → posting_get → posting_save_analysis → application_save를 호출했다. 별도 SDK 세션 결과로 대체하지 않았다.

## 성공 흐름

- 직무 분석 89점과 필수 요건 충족, 참고 평가 안내 및 분석 Markdown 저장을 확인했다.
- 자소서 초안은 126자·85점이며 항목별 배점·점수 근거·감점 이유·본문 인용이 응답과 Markdown에 포함됐다.
- 이력서는 강점·부족한 근거·개선안과 두 관점을 반환하고 score:null 및 qualitative 모드를 유지했다.
- 같은 자료를 다시 읽고 표현을 수정한 자소서를 새 버전으로 저장했다. 수정본은 140자·86점으로, 문장 연결에 따른 가독성 1점 차이다. 점수 상승을 품질 보장이나 합격 확률로 표현하지 않는다.
- 분량·공백 기준 누락을 가정한 별도 버전은 형식 항목 unknown/null, 총점 null, needs_confirmation 및 기준 확인 안내를 반환했다.

## 실패와 보존 확인

- 없는 자료는 FILE_NOT_FOUND와 상대 경로 확인 안내를 반환했다. 자료에 없는 인용은 INVALID_EVIDENCE로 거부됐다.
- 평가 null과 빈 answer_quotes는 MCP 입력 검증에서 저장 전에 거부됐다. 처음 유보 항목의 인용을 빈 배열로 보냈을 때 이 검증에 걸렸고 저장 버전이 늘지 않았음을 확인한 후 본문 인용을 추가해 저장했다.
- unknown 항목도 answer_quotes 최소 1개가 필요하다는 기존 조건을 사용 문서에 명시했다. 제품 코드나 평가 배점은 변경하지 않았다.
- 완성 버전은 초안·이력서·수정본·유보 예시의 4개다. 실패 요청으로 추가 버전이나 임시 버전은 생기지 않았다.
- 첫 자소서 저장 직후의 기존 파일 6개와 최종 파일의 해시를 비교해 공고 기록·분석·원본 이미지·초안 버전이 그대로임을 확인했다. 가상 자료·입력 이미지·기존 달력의 해시와 수정 시각도 유지됐다.
- 공고는 analyzed, calendar:null이며 로컬 달력 등록과 Google 호출은 수행하지 않았다.
- 제출 전 Windows npm run check의 83개 테스트가 모두 통과했다(실패·건너뜀 0). 문서 32개·로컬 링크 67개·Git 제외 규칙과 diff 공백 검사도 통과했다.

## 남은 확인

- 사용자에게 가상 자소서·이력서와 평가를 보여주고 점수 이유·개선안의 이해 여부를 물었다. 답변 전 사용자 피드백 완료로 기록하지 않는다.
- 실제 지원 플랫폼이 정해지지 않아 플랫폼별 글자 수 대조는 수행하지 않았다. 이번 500자 기준은 가상 공고에 명시한 검증 조건이다.
- 이슈 #4에는 직접 호출·수정본·누락 안내를 완료로 반영하고 사용자 피드백과 플랫폼 조건을 구분한다.
