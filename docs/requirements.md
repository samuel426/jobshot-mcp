# 제품 요구사항

기준일: 2026-10-13. 저장소: `jobshot-mcp`, 제품명: JobShot.

## 목적과 사용자

채용공고를 캡처해 두고도 마감일과 준비 항목을 다시 찾느라 시간을 쓰는 개인 구직자를 돕는다.
사용자는 본인 기기와 본인의 AI 계정을 사용한다. 개발자 서버, 회원 관리, 중앙 자료 수집은 두지 않는다.
AI로 원하는 서비스를 구현할 수 있는지와 실제 사용자의 불편이 줄어드는지를 검증한다.

## 첫 버전 요구사항

| ID | 요구사항 | 확인 기준 |
| --- | --- | --- |
| R01 | 최초 개인 자료 등록 및 재사용 | `개인 자료/`를 안내하고 매 공고 분석 시 최신 원본을 읽음 |
| R02 | 캡처 입력 | Windows 복사·붙여넣기 사용 흐름을 우선 검증하고 파일 입력을 대안으로 제공 |
| R03 | 긴 이미지 보관·분할 | 원본을 보존하고 필요한 경우 읽기 좋은 겹침 구간을 둔 분할본과 좌표를 저장 |
| R04 | 공고별 폴더 | `공고/마감날짜_기업이름_직무/사진/` 구조, 미정 날짜와 이름 충돌 처리 |
| R05 | 분석만 하기 | 일정 등록 없이 직무 적합도와 짧은 근거를 제공하고 종료 |
| R06 | 선택적 일정 등록 | 사용자 요청에 따라 로컬 달력 등록, Google 전송은 별도 선택 |
| R07 | 월간 HTML | 현재 월로 시작, 오늘 강조, 이전·다음 월과 오늘 버튼, 공고 원문 링크 |
| R08 | 날짜 갱신 | 페이지를 열어둔 채 자정이 지나거나 다시 활성화돼도 오늘 표시 갱신 |
| R09 | 맞춤 서류 | 요청한 공고의 자소서·이력서 초안과 근거를 별도 저장, 원본 불변 |
| R10 | 문항별 100점 평가 | 배점·점수·근거·개선안을 제공하고 합격 확률과 구분 |
| R11 | 사용자 안내 | 처음 사용·입력 누락·지원하지 않는 입력에 실행 가능한 다음 행동 안내 |
| R12 | 개인화 | 지속적인 작업 방식 변경은 확인 후 로컬 설정에 저장 |
| R13 | 외부 캘린더 | 계정 연결·선택적 등록·수정·중복 방지, 실패 시 로컬 기록 보존 |
| R14 | 공개 저장소 | 실제 개인 자료·공고·OAuth 정보·생성물이 Git에 포함되지 않음 |

## 기본 대화 흐름

- 최초: 자료 위치 안내 → 사용자가 자료를 넣음 → 읽을 수 있는 자료와 누락을 확인.
- 원본만 보관한 공고는 `imported`다. AI 분석과 일정 등록 완료로 취급하지 않는다.
- 분석: 캡처 수신 → 원본 저장·필요 시 분할 → 공고 정보 확인 → 개인 자료 비교 → 적합도와 근거.
- 저장된 분석은 기본적으로 `analyzed`이며 달력에는 보이지 않는다. 분석만 요청하면 여기서 종료한다.
- 등록: 사용자가 원할 때 `tracked`로 바꾸고 로컬 달력을 갱신한다. Google 연동 요청 시에만 전송한다.
- 서류: 사용자가 요청한 문항과 글자 수 기준으로 초안·평가를 만든다.
- 개인 자료가 없으면 공고 정보 정리만 가능하다. 적합도와 맞춤 서류는 자료가 필요하다고 안내한다.
- 사용자가 원본을 갱신하면 다음 분석부터 새 내용으로 판단한다. 개인 자료 개선 조언은 요청 시 제공한다.

## 지원 범위와 제외

Windows 우선. macOS는 파일 입력부터 검증하고 클립보드는 클라이언트별로 지원 여부를 확인한다.
AI 채팅에 붙인 이미지가 MCP에 자동 전달된다고 가정하지 않는다. 첨부 파일 접근 가능 여부를 1단계에서 검증한다.
1단계는 `inbox/` 상대 파일 경로를 받는다. Windows용 별도 캡처 CLI는 사용자가 실행할 때 클립보드 이미지를 PNG로 저장한다.
Windows 실제 클립보드 저장과 Codex 대화창 첨부의 파일 접근·보존을 확인했다. 가상 공고로 파일 입력·stdio 흐름도 검증했다.
Codex 프로젝트 설정 적용과 App Server 임시 세션의 MCP 도구 발견·호출을 확인했다.
현재 앱 대화의 재연결 후 직접 도구 호출, Claude Code, macOS 실기기는 아직 미검증이다. 상세 조건은 [실사용 체크](client-validation.md)를 따른다.
채팅 전용 GPT 환경처럼 로컬 파일·MCP 접근이 없는 환경은 같은 기능을 보장하지 않는다.

첫 버전에서는 자동 지원서 제출, 시험 중 답안 제공, 대량 크롤링, 공개 공고 DB,
개발자 서버, Notion 연동, 상시 백그라운드 알림, Google 캘린더의 완전한 양방향 동기화를 구현하지 않는다.
역량검사·코딩테스트·면접은 요청 시 준비 계획과 연습을 돕는 범위이며 전용 학습 시스템은 후속 작업이다.

## 친구들과 검증할 질문

본인이 동의한 피드백만 수동으로 받는다. 자동 사용량 수집은 하지 않는다.

1. 설명 없이 첫 공고 분석까지 갈 수 있었는가? 막힌 지점은 무엇인가?
2. 달력에서 다음 마감 공고와 원문을 빠르게 찾을 수 있는가?
3. 기존 방식보다 정리 시간이 줄었는가? 본인이 느낀 차이는 어느 정도인가?
4. 평가 근거가 실제 서류 수정에 도움이 됐는가?
5. 다시 사용하고 싶은가? 가장 불편한 한 가지는 무엇인가?
