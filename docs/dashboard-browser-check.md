# 로컬 달력 브라우저 검증

자동 DOM 검사는 실제 브라우저의 레이아웃·CSP 적용을 보증하지 않는다. 아래 검사는 가상 공고 6개만 사용하며 실제 작업 폴더의 개인 자료·공고·인증 정보를 읽지 않는다.

## 실행

프로젝트 루트에서 빌드한 뒤 실행한다.

```sh
npm run build
node scripts/preview-dashboard-check.mjs
```

출력된 `preview` 주소를 브라우저에서 연다. 서버는 무작위 포트의 `127.0.0.1`에만 바인딩하며 정해진 가상 페이지 외에는 제공하지 않는다. 검증용 HTML은 `tmp/dashboard-browser-check/`에 생성된다. 검사가 끝나면 터미널에서 Ctrl+C로 서버를 종료한다.

이 서버는 개발 검증용이다. 제품의 `dashboard/index.html`은 계속 서버 없이 사용한다. `file://` 접근 제한이나 브라우저 보안 설정을 바꾸지 않는다. HTTP 검증 결과를 파일 직접 열기 검증으로 기록하지 않는다.

## 화면과 조작

1. 한국 시간의 현재 월·오늘 강조, 등록 수 6개와 날짜 미정·상시 목록 2개를 확인한다. 이번 달/7일 이내 수는 실행 날짜에 따라 달라질 수 있다.
2. 이전·다음 달을 이동하고 12월→1월의 연도 전환을 확인한다. 오늘 버튼으로 현재 월에 돌아온다.
3. 가상 공고의 원문 링크를 직접 눌러 새 탭의 ‘가상 공고 원문 확인’ 페이지가 열리는지 확인한다. 링크는 실제 채용 사이트로 이동하지 않는다.
4. 너비 320·390·768·1440 CSS 픽셀에서 월 제목·버튼·공고·미정 목록을 확인한다. 좁은 화면에서 월 이동 버튼이 겹치거나 글자가 쪼개지지 않아야 한다.
5. 좁은 화면에서 안내를 따라 달력을 가로로 스크롤한다. 달력 영역에 키보드 초점을 두고 오른쪽 방향키로 오른쪽 날짜에 접근할 수 있어야 한다. 달력 내부 스크롤과 페이지 전체의 가로 넘침을 구분한다.

브라우저 너비 모사는 휴대전화의 터치·Safari·Android Chrome 실기기 검증이 아니다. 화면 크기 변경을 사용했다면 확인 후 원래 크기로 복원한다.

## CSP 실제 적용

출력된 `csp` 주소는 같은 제품 HTML·CSP에 검사 코드를 추가한 별도 페이지다. 검사 코드만 기존 nonce를 사용하며 제품 정책을 완화하지 않는다. 실제 제품 HTML에는 이 검사 코드를 넣지 않는다.

정상 달력 스크립트는 실행되고 아래 시도는 모두 차단돼야 한다.

| 시도 | 확인하는 차단 |
| --- | --- |
| nonce 없는 인라인 script | script-src-elem |
| nonce 없는 다른 출처의 script | script-src-elem |
| onclick 속성 | script-src-attr |
| 다른 출처로 fetch | connect-src |
| 다른 출처의 이미지 | img-src |
| new Function 실행 | script-src / eval |

다른 출처는 두 번째 루프백 서버이며 외부 인터넷으로 데이터를 보내지 않는다. 페이지의 `PASS: 6개 차단 + 정상 달력 실행`과 위반 상세를 확인한다. 출력된 `results` 주소의 `blocked_resource_requests`도 빈 배열이어야 한다. 두 결과를 함께 확인하며 CSP가 모든 종류의 공격을 막는다는 의미로 확대하지 않는다.

## 2026-11-04 결과

Windows Chrome의 실제 브라우저에서 월 이동·연도 전환·오늘 복귀·가상 원문 새 탭 이동을 확인했다. 320픽셀에서 오늘 버튼 글자가 두 줄로 쪼개지는 문제를 고쳤다. 가로 스크롤 안내, 초점 표시와 키보드로 이동할 수 있는 영역을 추가했다.

320·390·768·1440픽셀 화면을 확인했고, 측정한 320·768·1440픽셀에서 페이지 전체 가로 넘침은 없었다. 390픽셀에서 방향키로 오른쪽 끝 날짜에 접근했고 320픽셀에서 다음 달·오늘 버튼을 직접 눌렀다. 긴 기업명·직무, 날짜 미정·상시 카드도 확인했다.

CSP 6개 시도 차단·정상 달력 실행·예상하지 않은 스크립트 실행 없음과 대상 서버 요청 0건을 확인했다. 이 결과는 루프백 HTTP 검증이며 파일 직접 열기와 휴대전화 실기기는 이번에 수행하지 않았다.
